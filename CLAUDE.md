# 7A-app — Application Source Code

## Contributing hats

### As Developer
- Implement what's designed in `4B-architecture/` and specified in `5A-specs/`
- Follow the build sequence in `6C-build-plan/`
- Tests live here alongside the code, not in `5B-quality/`

## What belongs here
- Application source code
- Test code (unit, integration, e2e)
- Build configuration, package manifests
- Local development tooling (linters, formatters, scripts)

## What does NOT belong here
- Architecture decisions or design docs → `4B-architecture/`
- Detailed specs → `5A-specs/`
- Test strategy or QA reports → `5B-quality/`
- Build milestones or implementation plan → `6C-build-plan/`
- Mockups or wireframes → `4A-design/`

## Read before producing work
- `0A-ceo/hats.md` — Developer profile
- `6C-build-plan/implementation-plan.md` — what to build next
- `4B-architecture/system-design.md` — how it's structured
- `5A-specs/` — detailed contracts to implement against
- `4A-design/interaction-model.md` — what the user expects

## Downstream consumers
- `5B-quality/reports/` — test results from this code
- `6A-marketing/screenshots/` — built product generates marketing materials
- `6B-rollout/` — built product gets distributed
